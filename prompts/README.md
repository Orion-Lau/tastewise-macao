# prompts/ · QwenPaw 智能体提示词资产

每个文件对应一个智能体，结构统一：**系统提示词**（整段粘贴进 QwenPaw 的 System/人设栏）、
**用户消息格式**（后端 `server/agents/*.js` 的 `buildPrompt()` 将按此拼装）、**调优用例**
（与 `server/agents.test.mjs` 红线断言一一对应，作为平台上调优的验收标准）。

## 使用步骤

1. 在 QwenPaw 建智能体，名称建议与文件名一致（如 `aoweizhiyi-assistant`）。
2. 粘贴系统提示词；按文件头部标注设置温度。
3. 用「调优用例」里的输入在平台对话框实测：不达标 → 改提示词 → 复测，
   每一轮截图并记入 `docs/qwenpaw-log.md`（这就是开发过程证明）。
4. 后端接通后，用 `npm run eval:live` 批量回归全部红线。

## 通用约定（所有智能体一致）

- **输出必须是裸 JSON**：不要 markdown 代码块、不要解释文字。这是调优第一课——
  代码层直接 `JSON.parse`，多一个 ``` 都会失败。
- **只使用注入数据**：店铺信息以用户消息里的 JSON 为唯一事实来源，缺什么就说不确定，
  禁止用模型自身知识补全（如自行推断某菜"应该"含什么）。
- **代码层有二次校验**：提示词是第一道防线，`validate()` 是第二道；两道都过才算过。

## 温度建议

| 智能体 | 温度 | 理由 |
|--------|------|------|
| assistant / translator / onboarding / menu-extractor | 0.2–0.3 | 事实性输出，要稳 |
| faq-generator | 0.4 | 略需组织语言 |
| marketing | 0.7 | 需要文采，红线由约束和代码层兜住 |

## 为什么没有 risk-checker 的提示词

风险检查（"文字提及花生但未勾选坚果"类矛盾检测）**有意保留纯代码实现**
（`server/agents/risk-checker.js`）：安全裁定要求 100% 可复现、可审计，
不交给生成式模型。这是架构决策，策划书技术方案章节可直接引用。
