# prompts/ · QwenPaw 智能體提示詞資產

每個文件對應一個智能體，結構統一：**系統提示詞**（整段粘貼進 QwenPaw 的 System/人設欄）、
**用戶消息格式**（後端 `server/agents/*.js` 的 `buildPrompt()` 將按此拼裝）、**調優用例**
（與 `server/agents.test.mjs` 紅線斷言一一對應，作爲平臺上調優的驗收標準）。

## 使用步驟

1. 在 QwenPaw 建智能體，名稱建議與文件名一致（如 `aoweizhiyi-assistant`）。
2. 粘貼系統提示詞；按文件頭部標註設置溫度。
3. 用「調優用例」裏的輸入在平臺對話框實測：不達標 → 改提示詞 → 複測，
   每一輪截圖並記入 `docs/qwenpaw-log.md`（這就是開發過程證明）。
4. 後端接通後，用 `npm run eval:live` 批量回歸全部紅線。

## 通用約定（所有智能體一致）

- **輸出必須是裸 JSON**：不要 markdown 代碼塊、不要解釋文字。這是調優第一課——
  代碼層直接 `JSON.parse`，多一個 ``` 都會失敗。
- **只使用注入數據**：店鋪信息以用戶消息裏的 JSON 爲唯一事實來源，缺什麼就說不確定，
  禁止用模型自身知識補全（如自行推斷某菜"應該"含什麼）。
- **代碼層有二次校驗**：提示詞是第一道防線，`validate()` 是第二道；兩道都過纔算過。

## 溫度建議

| 智能體 | 溫度 | 理由 |
|--------|------|------|
| assistant / translator / onboarding / menu-extractor | 0.2–0.3 | 事實性輸出，要穩 |
| faq-generator | 0.4 | 略需組織語言 |
| marketing | 0.7 | 需要文采，紅線由約束和代碼層兜住 |

## 爲什麼沒有 risk-checker 的提示詞

風險檢查（"文字提及花生但未勾選堅果"類矛盾檢測）**有意保留純代碼實現**
（`server/agents/risk-checker.js`）：安全裁定要求 100% 可復現、可審計，
不交給生成式模型。這是架構決策，策劃書技術方案章節可直接引用。
